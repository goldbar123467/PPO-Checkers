# Contributing

Small, evidence-backed changes are welcome. Open an issue before changing rules, observation/action encoding, PPO semantics, evaluation design, or artifact formats; those boundaries require migration and reproducibility review.

## Development gate

```bash
uv sync --locked --all-groups
npm --prefix web/checkers ci
make check
npm --prefix web/checkers audit --audit-level=moderate
npm --prefix web/checkers run lint
npm --prefix web/checkers run typecheck
npm --prefix web/checkers test
npm --prefix web/checkers run build
npm --prefix web/checkers run test:e2e
```

Add tests for behavior changes. Keep rules symbolic. The Python engine is the reference: a rules, encoding, or network change must land in both `src/checkers` and `web/checkers/src/engine`, followed by a regenerated parity fixture (`scripts/export_browser_policy.py`). Do not update generated metrics by hand or claim strength from training loss. Record config, seed, revision, environment, and artifact hashes for experiments.

## Data and secrets

Do not submit checkpoints, optimizer state, caches, raw/reviewed datasets, run directories, or credentials. The only committed weights are the browser export in `web/checkers/src/model`, regenerated by the export script from the published release bundle. Tiny reviewed fixtures with provenance and compatible licensing are acceptable. CI never downloads the release bundle.
