# Iteration 000022 — Verify PPO-Clip by hand

## Objective

Implement only the loss and one-minibatch update path after freezing a literal four-transition
oracle and a directional clipping falsifier.

## RED / corrections / GREEN

The suite began with a missing `ppo.py` collection failure (`000082-*`). The first implementation
correctly rejected two float64 oracles whose `torch.full` old-logprob fixtures had silently become
float32 (`000083-*`). After explicit dtype correction, a test used `zip(strict=True)` on adjacent
views with intentionally different lengths; this test bug was fixed (`000084-*`).

The behavioral suite then passed 22 tests. The strict audit exposed formatting, stub typing, magic
constants, and twelve uncovered validation paths (`000086-*`). The final gate passes 31 tests,
strict mypy and Ruff, with 164/164 statements and 56/56 branches covered (`000087-*`).

## Result

- every T3 scalar matches the independent oracle within `1e-12`;
- T4 probabilities move monotonically in the advantage direction, clip, and plateau;
- default advantage normalization uses population variance and explicit epsilon;
- rollout conversion preserves stored masks and trainable source indices;
- the update changes parameters, reports the pre-clipping norm, and leaves the global gradient at
  the declared clipped bound;
- k3 KL and strict clip fraction are diagnostics, with the target-KL stop flag surfaced.
