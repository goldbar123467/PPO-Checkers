## Rejected smoke evidence

The first real RTX 5070 recovery smoke was prepared from the immutable update-170 source into
`runs/checkers-ppo/phase7-a0-seed0-c8207ca-recovery-smoke`. One bounded update completed normally:
update 171, global step 1,400,832, logging step 188, elapsed training time 1,041.196 seconds, zero
sample-legality violations, zero mask-oracle disagreements, and a durable reloadable checkpoint.
The original source checkpoint and metrics hashes remained
`8cad9297309ee4788c18904dd8a552e6a63af09ba05fba9b6dbc2604acae61d2` and
`90ba4555ac2d9737208c6fd951104f377215ba297e1ce71d9f26aff918437f0a`.

RC7 was nevertheless rejected for two independent audit defects:

- The live monitor reported `CRASHED` during checkpoint loading because runtime `started_at` used
  the later application timestamp rather than the operating system's process creation time.
- The post-run audit rejected optimizer placement even though all 66 parameters and 132 Adam
  moment tensors were on CUDA. Its 66 finite scalar `step` tensors were on CPU, which is PyTorch's
  expected placement for non-capturable Adam.

The rejected smoke directory is retained unchanged as diagnostic evidence and is prohibited from
production continuation.

## Correction

Runtime identity now records the exact psutil process creation timestamp. The optimizer audit now
requires every parameter and non-step moment tensor on the configured device, verifies every
optimizer tensor is finite, requires each `step` tensor to be scalar, and records the scalar-step
devices explicitly. A second bounded CUDA smoke must be prepared independently from the original
source and pass both live and post-run checks before RC7 can become green.
